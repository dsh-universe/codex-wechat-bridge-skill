# Codex → WeChatbot

Connect Codex to a personal WeChat account using Tencent's iLink Bot API. Messages flow through
long-polling (`getupdates`) — no public endpoint or webhook needed. Replies are generated by calling
an LLM API directly (no per-message CLI process), which keeps latency low.

## When to use

- User wants Codex to talk to them over personal WeChat (a bot contact in their own WeChat).
- User wants a WeChat bridge they can run locally: scan QR to log in, then the bot replies to DMs.

Do not use for WeCom (企业微信), official-account article publishing, or group messaging (iLink bot
identities generally cannot receive ordinary group events).

## Quick start

1. Ensure Python 3.10+ with `requests` (and `cryptography` for media if needed):

   ```bash
   pip install requests
   ```

2. Copy the config template and fill in real values:

   ```bash
   cp config.example.json config.json
   # edit config.json: llm_base_url / llm_token / llm_model
   ```

   The WeChat iLink credentials (`account_id`, `token`, `home_channel`) are filled automatically by
   the QR login step — do not hardcode them.

3. Log in by scanning a QR with WeChat:

   ```bash
   python scripts/wechat_bridge.py login
   ```

   This requests a QR from iLink, prints the link, waits for you to scan and confirm, then saves the
   new bot credentials back into `config.json`.

4. Run the bridge:

   ```bash
   python scripts/wechat_bridge.py run
   ```

   The bridge long-polls incoming messages and replies by calling the configured LLM API.

## Commands

- `login` — generate QR, wait for scan, save iLink credentials.
- `poll` — fetch new messages once and print them.
- `run` — long-poll daemon; reply to each DM via the LLM API.
- `send "text"` — send a text message to the configured home channel.

## Architecture notes

- Inbound: `POST ilink/bot/getupdates` with `get_updates_buf`; each reply must echo the peer's latest
  `context_token`.
- Outbound: `POST ilink/bot/sendmessage` with `item_list` text items.
- Reply: `POST {llm_base_url}/responses` (OpenAI Responses API shape) with `model` + `input`; if an
  `instructions_file` is set, its contents are sent as `instructions`.
- Long-polls and context tokens persist under `state/`.

## Security / hygiene

- `config.json` and `state/` are gitignored — never commit real tokens, bot IDs, or provider keys.
- The bot ID (`account_id`) and provider addresses are private to each user; keep them out of any
  shared example or docs.
- The model provider sees whatever the user writes to the bot; tell users this when it matters.
